# Pixiv Loader

Локальное веб-приложение для массового скачивания иллюстраций с **Pixiv**: очередь задач,
прокси `socks5`/`http`, авторизация через `cookies.txt`, возобновление загрузок после
перезапуска и живой журнал событий.

| Слой      | Технология                | Порт  |
|-----------|---------------------------|-------|
| Бэкенд    | Python + FastAPI + SQLite | `8002` |
| Фронтенд  | React + Vite + Tailwind   | `3002` |

---

## Быстрый старт

### 1. Бэкенд

```bash
cd backend
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

pip install -r requirements.txt
python run.py            # → http://127.0.0.1:8002
```

### 2. Фронтенд

```bash
# из корня проекта
npm install
npm run dev                  # → http://localhost:3002 (порт закреплён в vite.config.js)
```

> Порт фронтенда и его HMR-сокет закреплены за **3002** в `vite.config.js`.
> Если страница «самообновляется», а в консоли ошибка про порт 3000 — значит,
> запущен старый экземпляр Vite: закройте его и перезапустите `npm run dev`.

> Если бэкенд не запущен, интерфейс автоматически переключается в **демо-режим**
> (полностью рабочая симуляция очереди, логов и настроек) — удобно для знакомства.
> Как только сервер поднимется на `127.0.0.1:8002`, приложение само подключится к нему.

### 3. Всё на одном порту (опционально)

```bash
npm run build        # соберёт фронтенд в dist/
python backend/run.py  # бэкенд начнёт раздавать dist/ на :8002
```

## Поддерживаемые ссылки

| Вид | Пример |
|-----|--------|
| Поиск по тегу | `https://www.pixiv.net/en/tags/初音ミク/artworks` |
| Старый формат поиска | `https://www.pixiv.net/search?q=猫&s_mode=tag&type=artwork&r=1` |
| Профиль автора | `https://www.pixiv.net/en/users/2033916` |
| Иллюстрации автора | `https://www.pixiv.net/en/users/2033916/illustrations` |
| Отдельный пост | `https://www.pixiv.net/en/artworks/112233445` |

## Структура файлов на диске

```
{корневая папка}/pixiv/{тег из ссылки}/(1)_112233445_p0.jpg
                                       (2)_112233445_p1.png   ← вторая страница того же поста
                                       (3)_112233445_p2.jpg
                                       (4)_112233999_p0.png   ← следующий пост

{корневая папка}/pixiv/{Имя автора}_(pixiv_{ID автора})/(1)_98765432_p0.jpg
                например:  pixiv/shiratama_(pixiv_2033916)/…
```

* имя папки для **ссылок на автора** — `{Имя автора}_(pixiv_{ID автора})`:
  имя (ник) подставляется автоматически при старте задачи из профиля Pixiv
  и сохраняется в БД; если имя получить не удалось, папка останется `pixiv_{ID}`;
* `(N)` — порядковый номер **каждого файла**, уникален в пределах папки задачи:
  `(1)_123_p0`, `(2)_123_p1`, `(3)_123_p2`, `(4)_456_p0`… Посты обрабатываются
  **от старых к новым**, поэтому файлы старых постов получают младшие номера;
* `{ID}_p{страница}` — идентификатор поста и страница внутри поста;
* **защита от дублей:** перед скачиванием ищется файл с тем же `{ID}_p{страница}`
  (номер в скобках игнорируется) — найденный файл пропускается. Это же обеспечивает
  корректное возобновление: после перезапуска приложение продолжает задачу с места
  остановки, а не начинает заново; недокачанный файл докачивается по `Range` из `.part`.

### Ugoira (анимации)

Работы типа ugoira определяются автоматически (`illustType = 2`). Для них скачивается
не статичный постер, а **zip-архив с кадрами** из `/ajax/illust/{id}/ugoira_meta`,
например `(7)_118020966_p0.zip`. Поиск по тегу читает результаты из `body.illustManga`
(поле `illustId`), поэтому теги, содержащие только ugoira, тоже находятся и скачиваются.

## Очередь и обработка ошибок

* одновременно скачивается **только одна** задача, новые добавляются в конец очереди;
* мгновенная проверка дублей по БД при добавлении (в очереди или уже скачана — отклоняется);
* ошибка файла → повтор до **5 раз** (настраивается), затем задача помечается «Ошибка»,
  но скачивание **следующих файлов продолжается**;
* все изменения (статус, прогресс, байты, скорость) пишутся в SQLite **сразу**
  (commit after each action) — прогресс переживает перезапуск;
* «Очистить завершённые» убирает карточки из интерфейса, запись в БД остаётся («скачано»);
* «Выход» корректно останавливает воркер: активная задача сохраняется как «Пауза».

## Настройки (хранятся в БД)

| Поле | Описание |
|------|----------|
| Корневая папка | куда складывать `pixiv/{тег}/…` или `pixiv/{Имя автора}_(pixiv_{ID})/…` |
| Прокси | `socks5://127.0.0.1:1080` или `http://user:pass@host:3128` (есть кнопка «Тест») |
| `cookies.txt` | путь к файлу cookie в формате Netscape (экспорт из браузера) — нужен для поиска и профилей |
| Повторы | лимит повторов при ошибке файла (1–10, по умолчанию 5) |

## API (кратко)

```
GET    /api/health                    — живой ли сервер
GET    /api/state                     — задачи + настройки + активная задача
GET    /api/logs?since=N              — инкрементальные логи
POST   /api/tasks {url}               — добавить (с проверкой дублей)
POST   /api/tasks/{id}/pause | resume | restart
DELETE /api/tasks/{id}
POST   /api/tasks/clear-completed
GET/PUT /api/settings
POST   /api/test-proxy {proxy}
POST   /api/shutdown                  — корректное завершение процессов
```

## Структура проекта

```
backend/
  main.py              FastAPI: маршруты, CORS, раздача dist/
  worker.py            очередь: одна активная задача, повторы, докачка, пауза
  pixiv_client.py      разбор ссылок, cookies, прокси, ajax-API Pixiv
  db.py                SQLite: tasks, settings, history, logs (autocommit)
  run.py               запуск uvicorn на :8002
  requirements.txt
src/                   фронтенд (React + Vite + Tailwind, dev-порт 3002)
```
